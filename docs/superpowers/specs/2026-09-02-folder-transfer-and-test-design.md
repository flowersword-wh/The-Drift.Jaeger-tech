# 文件夹同步与测试框架设计

## 1. 背景

当前项目包含一个 TCP 客户端和一个 TCP 服务端，用于比较两个同步目录的
文件概览，并把客户端缺少的内容发送到服务端。

当前客户端和服务端已经支持通过命令行参数接收同步目录：

```text
server.exe <server-folder>
client.exe <client-folder>
```

本次设计针对现有同步主流程，解决子文件夹无法正确传输的问题，并补充可
重复运行的集成测试。

## 2. 当前实现

### 服务端

1. 从命令行参数读取服务端同步目录。
2. 遍历目录并生成 `fileoverview.txt`。
3. 监听本地 TCP 8080 端口。
4. 向客户端发送概览文件。
5. 接收客户端缺少的文件数量、文件名和文件内容。
6. 将接收到的内容保存到服务端同步目录。

### 客户端

1. 从命令行参数读取客户端同步目录。
2. 连接服务端 TCP 8080 端口。
3. 接收服务端发送的概览文件。
4. 遍历客户端目录并找出服务端缺少的内容。
5. 向服务端发送缺少内容的数量、名称、大小和内容。

## 3. 当前问题

当前目录遍历使用单层 `directory_iterator`，只能处理同步目录的直接子项。
它会同时返回文件和文件夹，但客户端把每个子项都当作文件处理。对文件夹
调用 `file_size()` 会导致错误。

即使跳过文件夹，现有传输协议只发送文件名，无法表达文件在子文件夹中的
相对位置。服务端保存文件时也不会自动创建父目录，因此无法恢复原有目录
结构。

## 4. 目标

本次改动应满足以下目标：

- 支持同步目录下任意层级的子文件夹；
- 保持文件的相对目录结构；
- 文件夹不作为普通文件发送；
- 服务端在保存文件前自动创建所需的父目录；
- 保持现有单文件同步行为；
- 命令行目录参数仍然可用；
- 使用现有 Rust runner 执行可重复的集成测试。

例如，客户端目录：

```text
client/
├── a.txt
└── docs/
    └── readme.md
```

同步完成后，服务端目录应包含：

```text
server/
├── a.txt
└── docs/
    └── readme.md
```

## 5. 设计方案

### 5.1 目录遍历

客户端和概览生成逻辑使用递归遍历，针对每个普通文件生成相对于同步根目
录的路径。例如：

```text
a.txt
docs/readme.md
```

目录本身不进入文件传输列表。文件路径统一使用
`std::filesystem::relative` 生成相对路径，避免传输客户端的绝对路径。

### 5.2 概览文件

概览文件每行记录一个普通文件的相对路径，不记录目录项。客户端根据相对
路径比较服务端已有文件，得到需要发送的文件列表。

### 5.3 文件传输

文件传输消息继续包含文件路径长度、文件大小、路径和文件内容，但路径字段
改为相对路径。这样可以兼容现有的单层文件，同时支持子目录文件。

### 5.4 服务端保存

服务端将接收到的相对路径拼接到同步根目录下，并在打开文件前创建父目录。
例如接收到 `docs/readme.md` 时，先确保 `docs` 存在，再写入文件。

服务端应拒绝包含绝对路径或跳出同步根目录的路径，避免路径穿越导致文件
被写入目标目录之外。

### 5.5 命令行参数校验

客户端和服务端在访问 `argv[1]` 前检查参数数量。参数缺失时打印用法并退
出，不应因为缺少参数访问无效内存。

## 6. 测试设计

继续使用 `test/runner` 中的 Rust 集成测试 runner，测试通过创建临时或测
试专用目录、启动服务端和客户端、等待进程结束，再检查结果目录。

至少覆盖以下场景：

1. 单层普通文件可以同步；
2. 子文件夹中的文件可以同步；
3. 两层及以上嵌套目录可以同步；
4. 空文件可以同步；
5. 服务端可以自动创建接收文件的父目录；
6. 空文件夹不会被错误地当成普通文件发送；
7. 已存在且内容不需要同步的文件不会重复发送；
8. 缺少命令行参数时客户端和服务端正常报错退出。

测试应同时验证：

- 进程退出码；
- 测试日志中的错误信息；
- 目标文件是否存在；
- 目标目录结构是否正确；
- 目标文件内容和源文件内容是否一致。

## 7. 错误处理

- 同步目录不存在或不是目录时立即报错退出；
- 目录遍历失败时记录错误，不继续发送不完整的概览；
- 收到非法路径时拒绝保存并记录错误；
- 创建父目录失败时终止当前传输并报告原因；
- 文件大小、路径长度或网络接收失败时终止当前传输；
- 客户端或服务端缺少必要命令行参数时显示正确用法。

## 8. 完成标准

满足以下条件时，本设计视为完成：

- 客户端能够递归发现所有普通文件；
- 服务端能够按相对路径创建目录并保存文件；
- 单层和嵌套目录测试全部通过；
- 不再对目录调用文件专用操作；
- 非法路径不会写出同步根目录；
- 客户端和服务端缺少命令行参数时不会崩溃；
- Git 工作区中的临时测试目录不会被误提交。
