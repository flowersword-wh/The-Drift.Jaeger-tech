# 测试用例详细说明

本文档说明 Rust 测试 runner 当前执行的每个测试用例，包括测试目的、准备的数据、校验方式和预期结果。

## 通用执行流程

runner 按固定顺序执行所有测试用例。每个测试用例都会准备自己的 sandbox 内容，生成唯一的 `run_id`，创建独立的 server/client 运行目录，启动 C++ 服务端和客户端，等待两个进程结束，然后执行通用校验和测试用例专属校验。

通用校验要求服务端运行目录包含客户端运行目录中的所有直接子项。当前校验只比较直接子项名称，不递归比较目录内容，也不比较通用校验中的文件内容。需要比较文件内容的测试会在自己的 `verify()` 中单独执行逐字节校验。

## default

实现文件：`src/case/default.rs`

测试目的：提供最常用的手动测试入口，验证开发者准备的 server/client 输入能否经过完整的 C++ server/client 流程。

测试准备：自动创建 `test/sandbox/default/server` 和 `test/sandbox/default/client`。如果 default sandbox 已存在且是目录，runner 会保留其中全部内容，不会删除开发者放入的文件。

测试校验：执行服务端包含客户端全部目录项的通用递归校验。default 不执行文件内容比较，但会递归校验子目录中的文件和目录结构。

预期结果：服务端和客户端正常退出，且服务端目录递归包含客户端目录中的全部目录项。

适用场景：手动准备测试文件、复现同步问题、验证普通 C++ 程序行为。

## just_demo

实现文件：`src/case/just_demo.rs`

测试目的：验证最基本的单文件同步流程。

测试准备：在客户端目录创建 `demo.txt`，内容为 `hello world`。

测试校验：通用校验确认服务端出现 `demo.txt`。当前该 case 不额外比较文件内容。

预期结果：客户端发送文件后，服务端和客户端均正常退出，服务端包含 `demo.txt`。

## empty_file

实现文件：`src/case/empty_file.rs`

测试目的：验证零字节普通文件可以被识别、发送和创建。

测试准备：在客户端目录创建大小为零的 `empty.bin`。

测试校验：读取服务端和客户端的 `empty.bin`，逐字节比较文件内容和文件长度。

预期结果：服务端生成同名零字节文件，文件内容完全一致。

## multiple_files

实现文件：`src/case/multiple_files.rs`

测试目的：验证一次连接中连续发送多个普通文件，以及包含常见空格和标点的文件名。

测试准备：在客户端目录创建 `multiple-1.txt`、`multiple-2.txt`、`multiple-3.txt` 和 `name with spaces (v1)-[test].txt`。

测试校验：逐个读取服务端和客户端文件并比较内容，确保多个文件都被传输且没有相互覆盖。

预期结果：四个文件全部出现在服务端目录中，文件内容逐字节一致。

## binary_file

实现文件：`src/case/binary_file.rs`

测试目的：验证同步逻辑不依赖文本编码，并覆盖小型二进制数据和较大文件传输。

测试准备：在客户端目录创建一个最小 PNG 文件 `sample.png`、包含零字节和高位字节的 `bytes.bin`，以及由重复模式生成的 1 MiB `large.bin`。

测试校验：逐字节比较三个文件的服务端副本和客户端源文件。

预期结果：三个文件均完整传输，二进制内容不发生截断、填充或修改。

## long_filename

实现文件：`src/case/long_filename.rs`

测试目的：验证文件名较长时，文件名长度编码、传输和目标文件创建仍然正常。

测试准备：创建一个由 240 个 `a` 加 `.txt` 构成的长文件名，以及一个由 250 个 `b` 加 `.txt` 构成、接近 Windows 单个路径组件长度限制的文件名。

测试校验：读取两个长文件名对应的服务端和客户端文件并逐字节比较内容。

预期结果：两个文件都能被正确传输并保持原文件名和文件内容。

## directory_transfer

实现文件：`src/case/directory_transfer.rs`

测试目的：明确记录当前不支持目录传输的行为，为后续实现目录递归同步保留回归测试入口。

测试准备：在客户端目录创建 `nested` 子目录，并在其中创建 `inside.txt`。

测试校验：通用直接子项校验会发现客户端存在服务端缺少的目录项，因此该测试应当失败。

预期结果：当前实现下该测试预期失败。runner 将它记录为 expected error，但不会因此返回失败退出码；目录传输功能实现后，应调整该测试的预期并增加递归内容校验。

## 运行产物

每轮测试使用独立的运行目录：`test/sandbox/<case>/runs/<run_id>/server` 和 `test/sandbox/<case>/runs/<run_id>/client`。进程日志位于 `logs/<case>/<run_id>/server.log` 和 `logs/<case>/<run_id>/client.log`。

发生进程错误、超时或校验失败时，控制台会输出测试名称、`run_id` 和对应的详细测试说明，便于定位本轮输入和日志。

## 当前未覆盖内容

当前测试尚未覆盖递归目录传输、符号链接、权限错误、文件名编码异常、断点续传、并发运行、网络中断恢复和文件内容校验失败注入。这些功能需要 C++ 协议或 runner 能力进一步支持后再增加对应测试。
